# The scratch of the disk

The work of the project needs more than the repository can hold: a Windows
environment to run the original editor, the runs of the oracle, the copies of
the tree that a measurement compares against. That material lives in
`~/genmsi-scratch`, **outside** the repository, and this file says what is in
it, so a session does not have to find out again.

The rule the project follows:

- the **harness** (the scripts that run something) and the **notes** (what the
  run proved) live in the repository;
- the **artifacts** (the runs, the caches, the copies of the tree, the Windows
  environment) live in the scratch;
- the **third-party binaries** (the original editor) live in the working tree
  and out of git: `Genmsi_20230711.backup/` is in `.gitignore`, and the
  oracle's tools look for it exactly there
  (`scripts/wine-oracle/run_oracle.sh`).

The scratch is disposable: nothing in it is the only copy of anything, and
every recipe that produced it is in the repository.

## What is in it

| Path | What it is | Disposable |
|---|---|---|
| `start/` | The scaffolding of the first-arrival work: the probes of the models, the harness that runs the original with a `START` value, and the Wine prefix of that unit | Yes: the probes are generated by the appendix of `odd/tasks/notas-start.md`, and the harness is `scripts/wine-oracle/run_oracle.sh` with the three changes the notes describe |
| `oracle/` | The runs of the original, one directory per model | Yes |
| `simultaneos-probes/` | The probes of the simultaneous-order work (eight models and the generator) | Yes: the generator is the appendix of `odd/tasks/notas-orden-simultaneos.md`, copied with two paths changed |
| `probes-reloj/` | The probes of the clock's granularity | Yes |
| `openmodel-e2e/`, `live-test/` | The models of the end-to-end checks of the app | Yes |
| `shots/` | The screenshots of the visual loop | Yes: the loop writes them again on every run (`GENMSI_SHOTS`) |
| `node-compile-cache/` | The cache of the frontend's bundler | Yes |
| `*.log`, `*_out.txt`, `*.json` | The answers and the transcripts of the measurements (the catalogue's before and after, the MCP's transcript) | Yes: the durable ones are in `odd/tasks/medida/` and `odd/tasks/medida2/` |

## The recipes that live in the repository

| What | Where |
|---|---|
| Run the original and compare its report with ours | `scripts/wine-oracle/` (`run_oracle.sh`, `compare-gpss.sh`, `make-benches.py`) |
| Extract the original's dialogs and manual | `scripts/wine-oracle/dfm.py`, `dfm-summary.sh` |
| Drive the MCP server and compare what it answers | `scripts/mcp-probe/` |
| Measure the cost of one frame of the replay | `crates/genmsi-app/scripts/measure-frame-cost.ts` |
| Review the interface with a browser | `crates/genmsi-app/scripts/check-visual-loop.sh` |

## The Wine environment

The original is a Delphi program for Windows, so it runs under Wine with its
own prefix (a Windows installation of its own). The prefix of the repository's
own oracle lives under `target/`; the units that need a prefix of their own
(the first arrival, with its own display) make one in the scratch. A prefix
is a few hundred megabytes and is never committed.
